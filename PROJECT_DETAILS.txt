SCENTIFY PERFUME STUDIO
========================

This file is a copy-friendly technical summary of the project.


1. PROJECT PURPOSE
------------------

Scentify Perfume Studio is a full-stack web application for creating and
ordering personalized perfumes.

Customers can:
- Browse perfume ingredients.
- Search the ingredient catalog.
- Build a custom fragrance.
- Add products to a shopping cart.
- Submit orders.
- Upload payment slips.
- Track order and payment status.
- Manage their profile and shipping address.
- Chat with customer support.

Staff and administrators can:
- Create, update, and delete ingredients.
- View customer orders.
- Update order status.
- Verify customer payments.
- View and respond to support messages.
- Create, update, and disable staff accounts.

8. BACKEND CONTROLLERS
----------------------

HealthController:
  Provides the public health endpoint.

ProfileController:
  Reads and updates the authenticated user's profile and shipping address.

IngredientController:
  Lists and searches ingredients. Staff/admin users can create, update, and
  delete ingredients.

OrderController:
  Creates orders, lists the current user's orders, lists administrative orders,
  and updates order/payment status.

ChatController:
  Provides customer chat and staff/admin chat endpoints.

StaffController:
  Creates, updates, and disables Firebase/Identity Platform staff accounts.

CurrentUser:
  Provides authenticated-user lookup and role authorization helpers.

10. SECURITY CONFIGURATION
--------------------------

Main production security file:
  backend/src/main/java/com/scentify/config/SecurityConfig.java

The production security configuration is active when the local profile is not
enabled. It provides:

- Stateless HTTP security.
- Disabled CSRF because the API is stateless.
- CORS support.
- OAuth2 JWT resource-server validation.
- Public access to /api/health.
- Public access to /actuator/health.
- Authentication required for every other endpoint.

Production authorization behavior:

  /api/health          public
  /actuator/health     public
  all other endpoints  authenticated

Expected request header:

  Authorization: Bearer <JWT_TOKEN>

Allowed CORS methods:

  GET, POST, PUT, PATCH, DELETE, OPTIONS

Allowed CORS headers:

  Authorization, Content-Type

CORS is configured with:

  CORS_ALLOWED_ORIGINS

Default value:

  http://localhost:3000

Local security file:
  backend/src/main/java/com/scentify/config/LocalSecurityConfig.java

The local profile allows requests without authentication and allows the local
frontend origin. This is intended only for local development.

Firebase configuration file:
  backend/src/main/java/com/scentify/config/FirebaseConfig.java

Firebase Admin uses Google Application Default Credentials. Do not commit
Firebase service-account JSON keys.

15. DEPLOYMENT
--------------

The intended production architecture is:

  React frontend
        |
        | HTTPS and JWT bearer token
        v
  Spring Boot API on Cloud Run
        |
        | Spring Data JPA and Flyway
        v
  Cloud SQL for MySQL

Backend Dockerfile:
  backend/Dockerfile

The Docker image:
- Builds with Maven and Eclipse Temurin Java 25.
- Runs with Eclipse Temurin Java 25 JRE.
- Exposes port 8080.
- Uses the Cloud Run PORT environment variable through Spring configuration.

Frontend hosting:
  firebase.json

Firebase Hosting serves:
  frontend/dist

Frontend production build:

  cd frontend
  npm run build

Cloud Run backend variables should include:

  DATABASE_URL
  DATABASE_USERNAME
  DATABASE_PASSWORD
  GOOGLE_CLOUD_PROJECT_ID
  CORS_ALLOWED_ORIGINS

Cloud SQL connection URL format:

  jdbc:mysql://google/scentify?cloudSqlInstance=PROJECT_ID:REGION:INSTANCE_NAME&socketFactory=com.google.cloud.sql.mysql.SocketFactory&cloudSqlRefreshStrategy=lazy

Production security requirements:
- Keep database passwords private.
- Use Secret Manager for production secrets.
- Do not commit service-account JSON keys.
- Add the deployed frontend domain to Identity Platform authorized domains.
- Set CORS_ALLOWED_ORIGINS to the deployed frontend origin.

17. COMMON SETUP ERRORS
-----------------------

Error:
  npm error ENOENT ... package.json

Cause:
  npm was executed from the repository root.

Fix:
  cd frontend
  npm run lint
  npm run build

Error:
  Maven MissingProjectException / no POM in current directory

Cause:
  Maven was executed from the repository root.

Fix:
  cd backend
  mvn clean test

or:

  mvn -f backend/pom.xml clean test

Error:
  Database connection failure

Possible causes:
- MySQL is not running.
- Database scentify does not exist.
- DATABASE_URL is incorrect.
- DATABASE_USERNAME or DATABASE_PASSWORD is incorrect.
- Flyway cannot apply the migration.

Error:
  JWT issuer or authentication failure

Possible causes:
- GOOGLE_CLOUD_PROJECT_ID is missing or incorrect.
- JWT_ISSUER_URI is incorrect.
- Firebase/Identity Platform is not configured.
- The frontend is sending a token from a different project.

Error:
  CORS failure in the browser

Possible causes:
- The frontend origin is not in CORS_ALLOWED_ORIGINS.
- The backend is not running on port 8080.
- The frontend VITE_API_URL points to the wrong backend.
